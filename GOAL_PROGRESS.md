## Crash and relayed-peer investigation (2026-10-15)

- The retained dump `/var/tmp/core.qbittorrent.3115717.1792088521` identifies the original fault in `GeoIPDatabase::readDataFieldDescriptor()`. `lookup()` selected leaf `id=18342313` for `93.137.252.1`, then attempted to parse a MaxMind pointer at file offset `43705087`. That pointer decoded to `3877715504`, outside the 50,883,239-byte database; unsigned size subtraction let the invalid offset pass the old check.
- The selected GeoLite2 City file is readable by the independent `mmdblookup` tool, which returns country `HR` for `93.137.252.1`. The qBittorrent reader had reversed the packed nibbles for 28-bit tree nodes: the left record's high nibble belongs in the high nibble of byte 3, and the right record's high nibble belongs in its low nibble. This disagreed with the [MaxMind DB format specification](https://maxmind.github.io/MaxMind-DB/).
- Corrected the left/right 28-bit decoding and added bounds checks for tree data offsets, pointer targets, and descriptor reads. Added `testgeoipdatabase`, which builds a synthetic 28-bit database whose left child has a nonzero high nibble. The test fails against the previous decoder (empty country result) and passes with the fix.
- Built `qbt_app` and `testgeoipdatabase` in the external `qb-build` directory. The focused Qt test executable and CTest target pass. The production service has not yet been switched to this fixed build.
- The peer-list entry `192.168.21.58:42664` is the local SSH forwarder endpoint: the established socket is owned by `ssh -R 54717:192.168.21.58:54716 -N pi3`, connected to qBittorrent's listener on this host. SSH forwarding does not preserve the original peer IP/port. qBittorrent currently reports `firewalled`; its existing `Proxied` tracking counts successful outbound proxy sockets and does not include this incoming forwarded connection. Peer display/status integration remains to be implemented and verified.

## Current implementation

- The qBittorrent relay lifecycle service owns relay selection, the router mapping, the incoming TCP tunnel, and qBittorrent's advertised relay address. The fallback monitor watches stalled downloads and starts no second torrent client.
- The selector prefers pi3 and uses bigquiet when pi3's relay path fails. It selects one relay at a time and moves the UPnP mapping with it.
- The incoming TCP path uses SSH reverse forwarding and a socat listener. The relay script searches for a free internal SSH port and repoints an existing socat listener when necessary, avoiding collisions with other SSH forwards.
- When fallback activates, qBittorrent binds to pi3's OpenVPN interface or bigquiet's WireGuard interface with proxying disabled, so TCP and UDP traffic use the selected relay directly. The selected relay forwards incoming UDP only when that VPN route is active. SOCKS remains available as a TCP-only fallback.
- The production stall threshold is 120 seconds. The monitor adds and reannounces HTTP trackers for stalled UDP-only magnets.
